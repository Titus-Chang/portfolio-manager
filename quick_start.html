Quick Start

Portfolio Manager
五分鐘上手指南

一套零建置（zero-build）的 AI 作品集系統：用後台視覺化編輯專案（含封面圖上傳）、匯出成資料檔、 再由公開作品集頁面自動渲染。沒有 npm、沒有 bundler，連本機伺服器都可以不要 —— 雙擊就開。

Vue 3 CDN Tailwind CSS CDN Vanilla JS localStorage Base64 圖片內嵌 No build step

瀏覽器把 file:// 視為不透明來源，一律擋掉 fetch， 所以讀不到 projects.json。但 <script src> 不受這個限制 —— 資料改成 JS 檔就繞過去了。

// projects.js 的內容就是這樣，沒有別的 window.PROJECTS = [ { "title": "...", "image": "data:image/jpeg;base64,...", ... } ];
◆ 載入順序是 projects.js 優先。 index.html 先看 window.PROJECTS， 有就直接用；沒有才退回 fetch('projects.json')。 所以兩種開法都通，同一個檔案不必改。 封面圖若是上傳內嵌的 base64，圖片也一起在 projects.js 裡 —— index.html + projects.js 兩個檔案就是完整作品集， 壓成 zip 寄給客戶對方雙擊就能看。
⚠ 編輯完要重新 Export JS。 projects.js 是靜態快照，後台改了資料它不會自己更新。 同時維護兩份（.js 與 .json）時，記得兩個都要重新匯出。

04第一次操作流程

從空白到一頁完成的作品集，大約需要五個動作。

  1. 開啟 admin.html
    左側是專案清單、右側是編輯表單。首次開啟若曾編輯過，會自動從 localStorage （key：projects_admin_data）還原上次的內容。
  2. 載入既有資料（可選）
    按右上角 Import JSON，選擇專案內附的 projects.json（已有 7 筆範例），立刻有東西可以練手。
  3. 新增與編輯專案
    + New 建立空專案 → 填寫欄位 → Save。 最上方的 Cover Image 可拖放／貼上專案截圖（詳見下一節）。 標籤（tags）在輸入框按 Enter 即新增，點標籤上的 × 移除。 Duplicate 可一鍵複製類似專案。所有變更都會即時寫入 localStorage，重新整理不會丟。
  4. 匯出資料
    Export JS 下載 projects.js（雙擊即可看，推薦）、 Export JSON 下載 projects.json（HTTP 供應用）。 兩者內容相同，只差包裝方式。下載的檔案要放回專案資料夾覆蓋原檔 （通常會落在「下載」目錄，記得搬過來）。
  5. 打開 index.html 驗收
    重新整理即可看到新卡片，含分類篩選與游標追蹤光暈。這就是要交出去給客戶／面試官看的那一頁。

05加上封面圖片

每個專案可以帶一張 16:9 封面圖，作品集頁面會把它滿版放在卡片頂端。純前端沒有後端可以存檔， 所以提供兩種模式 —— 大多數情況直接用第一種。

A · 上傳內嵌（推薦）
在 Cover Image 區塊拖放檔案、點擊選檔，或截圖後直接 Ctrl+V 貼上。 圖片會自動縮到長邊 1600px、轉成 JPEG，再以 base64 內嵌進資料檔。

好處是整份作品集就是一個檔案：JSON 搬到哪裡圖片就跟到哪裡， 連 file:// 直接開都看得到圖。
B · 外部連結 / 相對路徑
在圖片區塊下方的文字框填入 https://… 的網址， 或自建資料夾後填相對路徑，例如 images/cover.jpg。

JSON 保持輕薄，適合圖多、或圖片已放在 CDN／圖床上的情況。代價是檔案要自己顧， 相對路徑也必須以 HTTP 供應才讀得到。
⚠ 注意 localStorage 的 5 MB 上限。 內嵌圖片吃的是同一份配額，導覽列右上角的量表就是在看這個 —— 超過 80% 會轉成琥珀色。 真的滿了，後台會保住文字資料、跳出紅色警告並提醒你立刻 Export JSON （匯出的檔案永遠是完整的，含圖片）。圖多的話建議走上面的模式 B。
✎ 幾個實際會遇到的細節：壓縮一律輸出 JPEG，所以動態 GIF 會變成靜態、 PNG 透明底會填上卡片深色底；上傳完要按 Save 才會寫入； 想調整壓縮強度就改 admin.html 裡的 MAX_EDGE 與 JPEG_QUALITY。 圖片是選填的 —— 沒填的卡片就維持原本的純文字版面。

06分類設定

分類不是寫死的。點導覽列的 ▣ Categories（或表單裡的「管理分類…」）就能增減、 改名、換色、調整順序。設定會跟著資料一起匯出，作品集頁面的篩選按鈕由它產生。

新增
輸入名稱、選顏色、按 Add。代碼（value）會自動從名稱產生， 中文也可以。
刪除
沒有專案在用就直接刪。有專案在用會先要求你選一個改分到哪裡， 不會讓專案變成孤兒。
排序
▲▼ 調整順序，作品集頁面的篩選按鈕就照這個順序排。
✎ 名稱可以改，代碼不行。 專案是靠 value（代碼）對應分類的，所以它建立後就固定住 —— 這樣就不會出現「改個名字結果全部專案失去分類」的狀況。 顯示名稱 label 隨時可以改，改了作品集頁的按鈕文字就跟著變。

側欄的分頁標籤用的是代碼（Automation）， 下拉選單與標籤用的是完整名稱（Automation & Orchestration）， 所以代碼取短一點、名稱取完整一點，排版最好看。
⚠ 匯入舊檔可能出現「未定義分類」。 如果 JSON 裡的 category 值不在分類清單中，後台會用灰色虛線標籤 標示出來，Categories 按鈕上也會出現琥珀色的 +N! 提示。 打開分類設定，點一下就能把它補進清單。在補上之前資料不會被改動，也不會遺失。

作品集頁面則更寬容：它會把資料裡出現過的分類全部列成按鈕， 就算沒有定義也不會有點不到的卡片。

08資料結構

projects.json 最外層是一個物件，裝著分類設定與專案陣列兩份東西。

{ "categories": [ { "value": "automation", "label": "Automation & Orchestration", "color": "#7dd3fc" }, … ], "projects": [ … ] }
◆ 舊格式仍然通。 純陣列的 projects.json（沒有外層包裝）照樣讀得進去 —— 此時分類會自動從專案的 category 值推導出來， 名稱直接用代碼轉成標題大寫。projects.js 對應的是兩個全域變數： window.CATEGORIES 與 window.PROJECTS， 後者單獨存在也能用。

projects[] 的每個物件 —— 八個欄位、全部扁平、沒有巢狀。

{ "category": "automation", "metric": "-85%", "metricLabel": "Manual Workload", "title": "Autonomous Workflow System", "link": "https://example.com", "desc": "Project description here.", "image": "images/cover.jpg", // 或 "data:image/jpeg;base64,..." "tags": ["GPT-4o API", "Zapier Agents"] }
欄位型別說明
categorystring 對應 categories[].value 之一，決定卡片歸屬哪個篩選按鈕。 分類可在後台自由增減 —— 預設是 automation · marketing · enterprise · engineering，但這只是預設值而非固定選項。
metricstring 卡片上最大的那個數字，例：-85%、3x、3 Min。刻意用字串，方便帶符號與單位。
metricLabelstring 數字旁的小標，例：Manual Workload、CPA。
titlestring專案標題。
linkstring 整張卡片的連結網址；填 # 代表暫無連結。
descstring一到兩句成果敘述。
imagestring 選填。封面圖，卡片頂端 16:9 滿版顯示。可以是 data:image/… base64、完整網址，或 images/cover.jpg 這樣的相對路徑。 留空或載入失敗時，卡片自動退回純文字版面。
tagsstring[]技術／工具標籤，顯示為卡片底部藍色小標。

categories[] 的每個物件 —— 三個欄位。

欄位型別說明
valuestring 代碼，專案的 category 就是對應到這裡。 由名稱自動產生，建立後不可修改。
labelstring 顯示名稱，作品集頁的篩選按鈕文字。隨時可改。
colorstring 十六進位色碼，例 #7dd3fc。 用於後台的分類標籤（底色與邊框由它自動推導出透明度變化）。

陣列順序就是作品集頁篩選按鈕的順序。

✎ 想改分類的名稱或顏色，要動兩個地方：admin.html 的 categoryMeta / filterOptions， 以及 index.html 上方的篩選按鈕 data-filter。兩邊的 key 必須一致。

10疑難排解

會踩到的坑基本就這幾個。

index.html 顯示黃色錯誤橫幅，讀不到資料
橫幅現在會直接講出是哪一種原因，照著做就好。三種常見情況：

1. 用 file:// 雙擊但同層沒有 projects.js —— 到後台按 Export JS，把 projects.js 放到 index.html 旁邊。
2. HTTP 供應但 404 —— 檔名被改過或不在同一層。本頁預期的名字就是 projects.json，改成別的名字它不會自己去找。
3. JSON 語法錯誤 —— 陣列尾端多一個逗號、或檔案在寫入時被截斷。 重新 Export 一份即可。若尾端被填了 NULL 位元組（同步工具或防毒中斷寫入造成）， 本頁會自動略過那段並照常顯示，只給一個提醒。
後台改了東西，但作品集頁沒變
後台的即時儲存只寫入瀏覽器 localStorage，不會自動寫檔。 必須按 Export JS（或 Export JSON）下載，再把檔案覆蓋回專案資料夾 —— 純前端頁面沒有寫入本機檔案的權限，這一步只能手動。 兩份都在用的話，兩份都要重新匯出，否則 projects.js 會蓋掉 projects.json 的內容 （前者優先），你會以為改的東西沒生效。
作品集頁的篩選按鈕跟後台的分類不一樣
分類設定是跟著資料檔走的，所以改完分類要重新 Export（JS 或 JSON） 並覆蓋舊檔，作品集頁才會看到新設定。

另外作品集頁會把「資料裡出現過但沒定義」的分類也列成按鈕（名稱直接用代碼）， 所以如果看到多出來的按鈕，通常是某些專案還帶著舊分類值 —— 打開後台的 Categories 會看到琥珀色提示，點一下就能補進清單，或把那些專案改分到現有分類。
某個分類的標籤變成灰色虛線，寫著「未定義」
表示這個專案的 category 值不在分類清單裡 —— 通常是匯入了舊檔，或分類設定的 localStorage 被清掉了。 資料沒有損壞，只是找不到對應的名稱與顏色。 打開 ▣ Categories，最下方會列出這些值，點一下就能加進清單； 或直接在專案表單的下拉選單改成現有分類。
可以把分類代碼改成別的名字嗎？
不行，這是刻意的限制。專案是靠代碼（value）對應分類的， 如果代碼可以改，改完所有用到它的專案就會瞬間全部失去分類 —— 所以代碼建立後固定住，顯示名稱則隨時可以改，這已經涵蓋了實際需求。 真的要換代碼，就新增一個分類、把專案改分過去、再刪掉舊的（刪除時會自動幫你改分）。
卡片上的圖片沒出現
作品集頁面對讀不到的圖片是「靜默移除」—— 卡片會退回純文字版面，不會出現破圖。 所以看不到圖通常是路徑問題：相對路徑（images/cover.jpg） 必須以 HTTP 供應、且資料夾要跟 HTML 同層；外部網址則要檢查對方是否允許被引用。 最保險的做法是用後台上傳成內嵌 base64，路徑問題就整個消失。 另外別忘了上傳後要按 Save、再重新 Export JSON。
導覽列的量表變成琥珀色 / 跳出「localStorage 已滿」
內嵌圖片累積超過瀏覽器約 5 MB 的配額了。此時後台會退一步只存文字， 並提醒你立刻 Export JSON —— 匯出的檔案是完整的（含所有圖片）， 所以照做就不會丟資料，但在你匯出之前不要關掉頁面。 長期解法有三個：減少張數、把大圖改走外部連結／相對路徑， 或把 admin.html 的 MAX_EDGE 調小（例如 1200）、 JPEG_QUALITY 降到 0.7 左右。
圖片顏色怪怪的 / GIF 不會動了
上傳壓縮一律輸出 JPEG：動態 GIF 只會留下第一格，PNG 的透明區域則會被填上卡片底色 #0f172a（刻意選的，貼在卡片上看不出接縫）。 需要保留透明或動畫，就別走上傳，改用外部連結／相對路徑指向原始檔。
資料不見了 / 想重來
localStorage 綁定「瀏覽器 + 網域」：換瀏覽器、切換無痕模式、或從 file:// 改成 localhost，看到的都是不同的儲存空間。 真的要清空，開 DevTools → Application → Local Storage，刪掉 projects_admin_data；或直接 Import 一份 JSON 覆蓋掉。 重要編輯完成後就 Export 一份留底。
頁面樣式全跑掉、只剩白底黑字
Vue 與 Tailwind 都走 CDN，需要連得上網。離線環境或公司防火牆擋 unpkg／jsdelivr 時就會這樣。 長期離線使用的話，把兩個 CDN 檔案下載到本機再改成相對路徑引用。
想換掉標題文案與品牌顏色
文案：index.html 的 <header> 區塊（h1 與 subtitle）。 顏色：每個 HTML 最上方 :root 的 CSS 變數，主色改 --accent 與 --accent-light 即可整頁換色。
可以直接部署到 GitHub Pages 嗎？
可以，這是純靜態站台。整個資料夾推上 repo、開啟 Pages 即可； index.html 在 Pages 上是 HTTPS 供應，fetch 可正常運作。 建議把它改名成 index.html 當首頁，而 admin.html 留在本機使用即可。
